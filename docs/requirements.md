# 要件定義

更新日：2026-09-28。本書は完成時の要求を定義します。利用者の指定は「確定」、未指定の運用値・品質数値は「初期案」です。現在の実装範囲は下表と[基本設計](architecture.md)で確認してください。

## 1. 目的と対象

指定ディレクトリの文書から日本語テキストを抽出し、検索・発見に使えるタイトル、要約、キーワードを生成します。元ファイルは変更しません。GUI、検索画面、カタログ製品への直接登録は初期開発の対象外とし、連携用ファイルを出力します。

### 確定条件

- Windows 11、メモリ16GB、GPUなし。アプリケーションのPython実行環境は3.14以降のみ。
- 数十MB程度の文書が1,000件超。処理は夜間に行います。
- 文書内容を外部送信せず、無料のローカルAIを使用します。
- 必須形式はpptx/docx/xlsx/pdf。ppt/doc/xls/txt/mdは設定で有効化するオプションです。
- 画像だけの文書もOCR対象です。パスワード等で保護されたファイルはエラー記録してスキップします。

## 2. 機能要件

| ID | 要件 | 受け入れ条件 |
| --- | --- | --- |
| F01 | 複数の指定ルートを再帰走査。拡張子は大文字小文字を区別しない | 日本語・空白を含むパスを処理し、対象外拡張子・除外指定を無視する |
| F02 | pptx/docx/xlsx/pdfから本文・表・構造を抽出 | 各形式の評価文書から見出し、本文、表の文字と出典位置を取得する |
| F03 | ppt/doc/xls/txt/mdは個別に有効化 | 無効なら走査対象外。旧Officeの変換失敗を記録して継続する |
| F04 | タイトル・要約・キーワードを日本語で出力 | タイトル1–80文字、要約原則200–400文字・最大600文字、キーワード原則5–10個・最大15個。短文は水増ししない |
| F05 | 完全重複は1回だけ抽出・生成 | 同じバイト列のコピーはSHA-256で統合し、全所在パスを1レコードに保持する |
| F06 | 内容更新時は再処理、未更新なら抽出を省略 | 同サイズ・同更新日時の内容変更も検知する。既知の同一内容へ更新した場合は結果を再利用する |
| F07 | テキストのない画像・ページをOCR | 全画像PDF、画像のみのOffice、本文と画像の混在文書で、本文を重複させずOCR結果を統合する |
| F08 | 保護・破損・読取不可は個別エラー | 後続ファイルを継続し、保護解除やパスワード総当たりを試みない |
| F09 | 夜間の終了・中断から再開 | 成功済みの内容は再抽出しない。未完了のジョブ・OCRページは次回に引き継ぐ |
| F10 | バージョン変更による再処理を管理 | OCR・抽出設定の変更は抽出以降、モデル・プロンプトのみの変更は生成以降をやり直す |
| F11 | 結果・失敗・進捗を保存 | 成功、要確認、保留、エラー、重複、未更新の件数と処理時間を実行単位で確認できる |
| F12 | 削除・移動を反映 | 同内容の移動は再抽出しない。完全走査で確認できた削除だけ所在を無効化する |

### 現在の実装範囲

| 項目 | 状態と境界 |
| --- | --- |
| 走査・重複・更新 | SHA-256の全量照合、同内容の統合、抽出・生成の再利用を実装。1,000件超での性能と共有パスの動作は未評価。 |
| 形式 | 必須4形式と任意のtxt/mdを直接抽出。ppt/doc/xlsは設定時に拒否し、LibreOfficeは使用しない。 |
| OCR・保護 | PDFページ描画とOffice内部画像をOCRし、検出できた暗号化・明示的保護をスキップ。画像位置との対応、PDF文字層との重複排除、保護網羅性は未評価。 |
| メタデータ | CPU版llama.cppで生成し、引用・数値・キーワードの一部を原文照合。全レコードを`review_required`として出力し、日本語品質の合格判定は未実施。 |
| 再開・運用 | 抽出本文、完了済みPDFページ・Office画像のOCR文字列、AI分割結果を再利用。中断した文書の本文抽出は先頭からやり直す。永続ジョブ、公称メモリ上限、世代別出力、タスク登録は未実装。 |

### 抽出範囲

以下は受け入れ目標です。現在の抽出器が実際に扱う要素と警告は[基本設計](architecture.md)に記載します。

- docx：本文、表、ヘッダー・フッター。テキストボックス、脚注等の標準APIで取れない要素はOOXML補完の検証対象。取れない要素は警告し、完全抽出と偽らない。
- pptx：スライド見出し、テキスト、表、グループ図形、ノート。画像はOCR。SmartArt、埋込オブジェクト等は検出・警告し、必要なものを評価後に追加する。
- xlsx：シート名、非空セル、保存済み数式結果。式は実行・再計算しない。キャッシュがなければ式と欠損の警告を保持する。隠しシート・行列も対象とし、位置情報で識別する。画像は描画情報から抽出する。
- pdf：ページごとのテキストと位置。画像領域にもOCRを適用する。読み順・段組は実文書で評価する。
- txt/md：UTF-8/BOM付きUTFを優先し、CP932は明示設定で許可。文字化けを置換文字で隠さず、復号失敗を記録する。リンク先は取得しない。
- グラフの意味解釈、手書き、数式の意味理解、埋込添付ファイルの再帰抽出は初期対象外。画像中の印字はOCRするが、認識不能は要確認とする。

## 3. 重複・更新の厳密な定義

「重複」はファイル全体のバイト列が同じことです。見た目が同じ別形式、保存し直したOffice、類似文書は別文書です。本文の類似性だけで統合しません。

毎回ストリームで全対象のSHA-256を計算する厳密モードを標準にします。更新日時・サイズだけでスキップしません。未更新でも読み取りI/Oは発生しますが、抽出・OCR・AI処理は省略します。処理中に変化したファイルは保留し、結果を公開しません。

変更後に抽出失敗した場合、変更前の結果を現在の内容として出しません。現在の実装は該当パスと旧内容の関連付けを外します。パスごとの変更履歴は未実装です。全パスが消えた内容は完全走査後の現行カタログから除外します。

## 4. 非機能要件

以下は本運用の目標です。8GiBの合計メモリ監視やディスク残量による自動停止はまだ実装していません。

- メモリ：アプリと子プロセスの合計8GiBを初期上限案とし、OS等の余裕を残す。文書・OCR・LLMの重い処理は並列化しない。超過は記録して安全に終了・再開する。
- 性能：初回全件の一夜完了は約束しない。通常日の変更分を8時間以内に処理する目標は、CPU・OCR比率・更新数の実測後に確定する。件数だけで処理能力を見積もらない。
- 信頼性：1件の障害でバッチを停止しない。設定不正、DB破損、ディスク枯渇等の全体障害は終了コードを返して停止する。多重起動を防ぐ。
- ローカル処理：推論先はループバックのみ。稼働時はインターネット不要。モデル・ツールの初回取得は別途行い、本文・画像を外部送信しない。
- 原本保護：読み取り専用で扱う。マクロ、外部リンク更新、文書内命令を実行しない。AIにはツール実行権限を与えない。
- 再現性：依存・モデル・辞書・プロンプト・設定の版を記録する。同じ入力への生成文の完全一致は保証しない。
- 費用：有料API、Microsoft Office購入、GPUを前提にしない。採用物の利用条件・同梱ライセンスを台帳化する。

## 5. 日本語品質の受け入れ案

代表文書60件（必須各形式15件、うち画像・混在を計20件以上）を人が確認します。チューニング用と最終評価用を分け、最終評価で閾値を変更しません。

| 指標 | 初期の合格目標 |
| --- | --- |
| 通常テキスト抽出 | 指定した重要見出し・段落・セルの取得率95%以上 |
| 印字日本語OCR | 正解文字列に対するCERのマイクロ平均5%以下。縦書き・低画質は別集計 |
| タイトル | 原文の主題と整合する文書90%以上 |
| 要約 | 主要情報の網羅・日本語の読みやすさ各4/5以上を満たす文書90%以上 |
| 捏造 | 評価した要約で、原文にない人物・組織・数値等の重大な誤り0件 |
| キーワード | 上位5語のうち関連ありと判定される語の割合80%以上（5語未満は実際の語数を分母にする） |

OCRやAIの自己申告だけで合格を判定しません。認識不良、抽出欠落、根拠不足は`review_required`と理由を付け、通常の成功件数と分けます。
